# ShitCam Architecture (v1)

All core execution code is x86-64 NASM assembly: Windows x64 ABI
(RCX/RDX/R8/R9, 32-byte shadow space, 16-byte stack alignment,
callee-saved RBX/RBP/RDI/RSI/R12-R15), PE/COFF console executables,
kernel32 API only (no CRT). Python is used solely for helper scripts
(`tools/build.py`, `tests/run_tests.py`, `tools/bench.py`).

## Pipeline

```
source (.sc)
  -> lexer  (src/lexer.asm)   : bytes -> 24-byte tokens [kind][payload][line]
  -> parser (src/parser.asm)  : tokens -> 48-byte AST nodes
  -> interpreter (src/interp.asm) or compiler (src/compiler.asm)
```

`shitcam file.sc` / `run`: load → lex → parse → `interp_exec`.
`shitcam build file.sc`: lex → parse → emit NASM → assemble (bundled NASM)
→ link (VS `link.exe` + SDK `kernel32.lib`) → native `.exe`.

## Source layout

- `src/shitcam.asm` — entry `main`, CLI dispatch, `load_file`, `run_file`,
  `lextest/parsetest` debug paths, `build_file` driver, REPL loop.
- `src/lexer.asm` — tokenizer; 4 MB bump pool for strings/idents;
  fatal errors with file/line/column + caret.
- `src/parser.asm` — recursive descent; nodes live in a VirtualAlloc pool
  (`AST_NODES_SIZE`), child pointer arrays in a 4 MB data pool.
- `src/runtime.asm` — tagged values, heap objects, variables, functions,
  stdlib builtins, value printing.
- `src/interp.asm` — tree-walk evaluator (`interp_eval` returns type in
  RAX, payload in RDX) and statement executor (`interp_exec`).
- `src/import.asm` — module cache (64 entries: path + busy/done),
  stdlib-name check, circular detection.
- `src/compiler.asm` — v1 subset code generator + `nasm`/`link` driver.
- `include/shitcam.inc` — limits, value tags, token/AST kinds, Win constants.
- `include/winapi.inc` — kernel32 imports.
- `build/cfg.inc` — generated by `tools/build.py`: absolute NASM/link/SDK
  paths baked in for `shitcam build` (forward slashes).

## Runtime value model

Values travel as `(RAX=type tag, RDX=payload)`:

| tag | payload |
|---|---|
| 0 null | 0 |
| 1 bool | 0/1 |
| 2 int | i64 |
| 3 float | f64 bits |
| 4 string | NUL-terminated `char*` |
| 5 array | `[len][cap][16-byte (type,payload) items]` |
| 6 object | `[count][cap][24-byte (key,type,payload) entries]` |
| 7 func | table entry (compiler v1: interpreter only) |

Strings are immutable NUL-terminated buffers (lexer pool or HeapAlloc).
Arrays/objects grow by doubling (old block leaks by design: arena model,
freed on process exit — no GC in v1).

Variables: flat table (4096 × 24 bytes: name, type, payload or slot).
Lookup runs newest-to-oldest so inner scopes shadow outer ones; function
parameters use always-append slots (`rt_push_var`) so recursion is safe;
plain assignment updates the nearest existing binding. `rt_var_count`
save/restore delimits calls. Functions table: 256 × 32 bytes
(name, param count, params ptr, body node).

Truthiness: null/false/0/"" are falsy.

## Scopes and semantics decisions

- `{ }` blocks do NOT introduce scopes (flat, matches `x=20` inside `if`).
- `if`/`while` bodies are Blocks executed in the current scope.
- `return` sets a global flag consumed by the call site.
- Parse errors print `expected ...` + location; the process exits 1.

## REPL design

`shitcam repl` keeps a 1 MB cumulative transcript and evaluates each logical
input (brace-counted for multiline `fn`) in a CHILD process:
transcript → temp `.sc` → `shitcam --repl-echo tmp` with stdout/stderr
captured to a file. The parent displays only unseen tail bytes
(`repl_shown` counter), so replays never duplicate output; on child failure
the tail (error text) is shown without advancing the counter and the input
is rolled back. The REPL itself therefore survives any error. Bare
expressions echo their values in child mode (`--repl-echo`), except
`print`/`println` calls.

## Compiler v1 design

Subset (ints/strings/print/if/while/assign) with static per-variable types
and use-before-define errors. Each variable maps to `sc_vN resq 2`
(type, payload) in the generated `.bss`; string literals become `sc_sN`
byte lists (no escaping issues); control flow uses generated `L1...`
labels; division emits a zero check (`sc_div_zero`). Generation is
single-pass after parsing; unsupported nodes abort with
`Compile error at line N`. Driver spawns NASM (`-f win64`) then LINK
(`console/entry:main`, `kernel32.lib`), reporting `Built <name>.exe`.

## Stack discipline (hard-won rules)

- At any `call`, RSP%16==0. Push counts + `sub` sizes are chosen per site
  (odd pushes → `sub` ≡ 0 mod 16; even pushes → `sub` ≡ 8).
- Windows APIs (esp. 7-arg `CreateFileA`, `ExitProcess`, `CloseHandle`)
  fault on misaligned stacks — verified the hard way.
- Our own callees are push-first, so slightly-misaligned INTERNAL calls are
  tolerated, but external calls must be exact.
- XMM0–XMM5 are volatile across calls (float code reloads from GPRs).
- `rt_print_value` callers: compound-type paths must pop the entry `rbx`.
- Naked trampolines (`call f; ret`) shift the frame — use `jmp f`.
